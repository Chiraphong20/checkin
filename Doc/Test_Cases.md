# เอกสารกรณีทดสอบระบบ (Test Cases)

รวบรวม Test Scenario และขั้นตอนการตรวจสอบว่าระบบทำงานถูกต้องตาม Requirement

---

## 1. ทดสอบการเข้าสู่ระบบ (Authentication Testing)

| กรณีทดสอบ (Test Case) | ขั้นตอน (Steps) | ผลลัพธ์ที่คาดหวัง | สถานะ |
| :--- | :--- | :--- | :---: |
| พนักงานล็อกอินสำเร็จ | 1. กรอก Username รหัสผ่านที่ถูก<br>2. กด Login | ระบบแสดงหน้า Dashboard สำหรับพนักงาน | [ ] |
| ผู้ใช้งานกรอกรหัสผิด | 1. กรอก Username ที่มี แต่รหัสผิด | ระบบแจ้งเตือน "ข้อมูลไม่ถูกต้อง" ไม่เข้าหน้าแอป | [ ] |
| ทดสอบ Role การเข้าถึงหน้า Admin | 1. ใช้รหัสผ่านบัญชีพนักงานล็อกอิน<br>2. พิมพ์บังคับเข้า URL `/admin` | ระบบปฏิเสธ เด้งกลับหน้า Check-In หรือเตือนไม่มีสิทธิ์ | [ ] |

## 2. ทดสอบระบบฝั่งพนักงาน (Employee Flow Testing)

| กรณีทดสอบ (Test Case) | ขั้นตอน (Steps) | ผลลัพธ์ที่คาดหวัง | สถานะ |
| :--- | :--- | :--- | :---: |
| การกด Check-In เข้างานครั้งแรก | 1. เข้าระบบและกดปุ่มเข้างาน | ปุ่ม Check-In จะเปลี่ยน/Disable, บันทึกเวลาปัจจุบัน | [ ] |
| การกด Check-Out ออกงาน | 1. พนักงานเคยกดเข้างานมาแล้วค่อยกดออก | บันทึกเวลา Check-Out ลงฐานข้อมูลสำเร็จ | [ ] |
| พนักงานตรวจสอบประวัติ | 1. คลิกแถบ "ประวัติของฉัน" | แสดงข้อมูลตารางเวลาที่เคยบันทึกย้อนหลังถูกต้อง | [ ] |
| พนักงานแก้ไขโปรไฟล์รหัสผ่าน | 1. ไปหน้าโปรไฟล์ 2. พิมพ์รหัสเก่า และรหัสผ่านใหม่ | รหัสอัปเดต ต้องพ่นข้อความสำเร็จ และสามารถล็อกอินด้วยรหัสใหม่ได้ | [ ] |

## 3. ทดสอบระบบฝั่งแอดมินและการพิมพ์รายงาน (Admin & Payroll Flow)

| กรณีทดสอบ (Test Case) | ขั้นตอน (Steps) | ผลลัพธ์ที่คาดหวัง | สถานะ |
| :--- | :--- | :--- | :---: |
| เพิ่มบัญสภาพนักงานใหม่ | 1. กรอกข้อมูล Name, User, Pass เบื้องต้น<br>2. กด Save | ตารางพนักงานโชว์ชื่อใหม่ขึ้นมา | [ ] |
| แอดมินแก้ไขการลงเวลา (Manual) | 1. เลือกพนักงานที่ลืมลงเวลา<br>2. ระบุ "เวลาเข้า-ออกย้อนหลัง"<br>3. กด Save | ประวัติพนักงานอัปเดต เพิ่ม Note ไว้ว่าแก้โดย Admin | [ ] |
| รายงานเงินเดือนประมวลผลถูก | 1. เข้าเมนู ออกรายงาน/Payroll<br>2. เลือกเดือน | ระบบรวมชั่วโมงทั้งหมด และคำนวณเงินออกมาอย่างแม่นยำ | [ ] |
