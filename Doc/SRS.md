# Software Requirements Specification (SRS)
## ระบบ Employee Check-in & Payroll System

---

## 1. บทนำ (Introduction)
เอกสารฉบับนี้คือข้อกำหนดความต้องการซอฟต์แวร์ (SRS) ของระบบจัดการเข้างานพนักงาน ซึ่งจะเป็นระบบเว็บแอปพลิเคชันที่ช่วยในการทำงานของ HR เพื่อบันทึกเวลา ลดกระดาษ และคำนวณเงินเดือนได้อย่างแม่นยำ

---

## 2. ผู้ใช้งานของระบบ (Users)
1. **Admin (ผู้ดูแลระบบ/HR):** จัดการข้อมูลพนักงาน ควบคุมการเข้างานและออกรายงาน
2. **Employee (พนักงาน):** ผู้ใช้งานที่ทำการลงเวลาเข้าออกงานในแต่ละวัน

---

## 3. ความต้องการเชิงฟังก์ชัน (Functional Requirements)

### FR-01: ระบบบัญชีผู้ใช้ (Authentication)
| รหัส | ความต้องการ |
|---|---|
| FR-01-1 | ผู้ใช้ต้องเข้าสู่ระบบผ่าน Username/Password ได้ |
| FR-01-2 | ระบบต้องแยกระดับสิทธิ์ (Role) ระหว่าง Admin และ Employee อย่างชัดเจน |

### FR-02: ระบบพนักงาน (Employee Management)
| รหัส | ความต้องการ |
|---|---|
| FR-02-1 | Admin ต้องสามารถเพิ่ม แก้ไข ข้อมูลพนักงานได้ |
| FR-02-2 | Admin สามารถลบหรือปิดการเข้าถึงของบัญชีพนักงานที่ลาออกได้ |
| FR-02-3 | พนักงานสามารถดูและแก้ไขข้อมูลส่วนตัวของตัวเองได้ (Profile Employee) |

### FR-03: ระบบลงเวลา (Check-in System)
| รหัส | ความต้องการ |
|---|---|
| FR-03-1 | พนักงานสามารถกดปุ่ม Check-in เมื่อเริ่มงาน และ Check-out เมื่อเลิกงานได้ |
| FR-03-2 | ระบบต้องบันทึก วันที่ และ เวลาที่ทำรายการอัตโนมัติตาม Server |
| FR-03-3 | Admin ต้องสามารถลงเวลาแทนพนักงานได้ (Admin Manual Check-In) กรณีฉุกเฉิน |
| FR-03-4 | พนักงานและ Admin สามารถดูประวัติการลงเวลาได้ |

### FR-04: ระบบเงินเดือนและรายงาน (Payroll & Reports)
| รหัส | ความต้องการ |
|---|---|
| FR-04-1 | ระบบต้องสามารถประมวลผลชั่วโมงทำงานจากเวลา Check-in และ Check-out ได้ |
| FR-04-2 | ระบบต้องสามารถออกรายงาน (Payroll Report) สรุปยอดเงินเดือนพนักงานได้ |

---

## 4. ความต้องการที่ไม่ใช่เชิงฟังก์ชัน (Non-Functional Requirements)

### 4.1 ความปลอดภัย (Security)
- รหัสผ่านเข้าสู่ระบบต้องถูกประมวลผลด้วยฟังก์ชันการแฮช (เช่น Bcrypt)
- API ต้องมีระบบ Token JWT ป้องกันผู้ไม่มีสิทธิ์เข้าใช้งาน
- มีการแบ่ง Role การเข้าถึงหน้าเว็บของ Frontend 

### 4.2 ประสิทธิภาพ (Performance)
- ระบบต้องรองรับพนักงานลงเวลาพร้อมกันในช่วงเช้าได้โดยไม่ประมวลผลช้าเกิน 3 วินาที
- หน้า UI ต้องเป็น Responsive Design ใช้งานผ่านคอมพิวเตอร์และมือถือได้ดี
